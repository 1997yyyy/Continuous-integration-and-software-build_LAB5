# Шаг 1. What is Infrastructure as Code with Terraform?

Руководство: <https://developer.hashicorp.com/terraform/tutorials/docker-get-started/infrastructure-as-code>
(видео + текст, ~3 мин). Практических команд этот шаг не содержит — ниже конспект,
который используется в отчёте.

## Что такое IaC

**Infrastructure as Code (IaC)** — подход, при котором инфраструктура (серверы, сети,
контейнеры, DNS-записи) описывается в текстовых файлах конфигурации, а не создаётся
вручную через веб-интерфейсы или команды в терминале. Файлы хранятся в системе контроля
версий и применяются автоматически.

## Чем IaC лучше ручного управления

| Ручное управление | IaC (Terraform) |
|---|---|
| Действия нигде не записаны, повторить их сложно | Конфигурация — это код в git, её можно отревьюить и откатить |
| Окружения (dev/stage/prod) расходятся | Одна и та же конфигурация даёт одинаковый результат |
| Изменения делаются «на живом» и непрозрачны | Перед применением показывается план изменений |
| Документация устаревает | Код — и есть актуальная документация |

## Декларативная модель и рабочий цикл

Terraform — декларативный инструмент: описывается **желаемое конечное состояние**
(«контейнер nginx должен существовать и публиковать порт 8000»), а не последовательность
шагов. Terraform сам вычисляет разницу между текущим и желаемым состоянием.

Рабочий цикл состоит из трёх этапов:

1. **Write** — описать инфраструктуру в конфигурационных файлах HCL (`main.tf`);
2. **Plan** — `terraform plan` сравнивает конфигурацию с состоянием (`terraform.tfstate`)
   и с реальной инфраструктурой, показывая, что будет создано, изменено или удалено;
3. **Apply** — `terraform apply` выполняет только те действия, которые были показаны в плане.

## Ключевые понятия, которые используются в следующих шагах

- **Провайдер (provider)** — плагин, через который Terraform общается с внешней системой.
  В этой работе используется `kreuzwerker/docker`: он управляет контейнерами через Docker API.
- **Ресурс (resource)** — единица инфраструктуры, которой управляет Terraform
  (`docker_image`, `docker_container`). У ресурса есть тип и имя, вместе они дают адрес:
  `docker_container.nginx`.
- **Состояние (state)** — файл `terraform.tfstate`, в котором Terraform хранит соответствие
  между ресурсами конфигурации и реальными объектами (ID контейнеров, образов) и их атрибуты.
- **Провайдеры и версии** — версия провайдера фиксируется в блоке `required_providers`,
  а точные версии и контрольные суммы — в файле `.terraform.lock.hcl`.

## Отличие от imperative-подхода

Императивный скрипт (`docker run ...`, `docker rm ...`) выполняет шаги «как сделать».
Если запустить его дважды, результат будет разным (второй контейнер либо не создастся,
либо возникнет конфликт имён). Terraform-конфигурация идемпотентна: повторный `apply`
без изменений конфигурации не делает ничего.
